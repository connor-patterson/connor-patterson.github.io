Performance case study

A 58 second quote flow was too long.

A high volume insurance quoting flow had accumulated repeat work in the browser and API path. I profiled the actual journey, removed the waste in measured steps, and kept the release grounded in production telemetry.

58.75s to 29.08s Tracked sales flow, a 50.51% reduction
66.43% Lower Vehicle Detail latency, measured week over week
24.3% Lower Review Quote latency after supporting changes shipped

The path through it

I started with the real request path.

  1. Find the expensive steps

    Used real user monitoring and browser plus API profiling on the tracked flow.

  2. Remove repeat work

    Hoisted converter calls and avoided updates that produced no meaningful state change.

  3. Cache where it was safe

    Applied endpoint and Redis caching while preserving freshness requirements.

  4. Collapse duplicate requests

    Deduplicated work already in flight instead of asking the same question twice.

  5. Ship with proof

    Used automated checks, code review, release readiness, and production telemetry to confirm the result.

My part

I stayed with it through production.

I drove the profiling, implementation, coordination across codebases, and production readiness work. The latest observed total reached 26.09 seconds after the initial measured improvement.
